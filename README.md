# job-posting-writer — AI求人票・スカウトメール生成デモ（コンプライアンスチェック付き）

「求人票づくり・スカウト文作成を0から行う必要がなくなる」の実証。**APIキー不要でそのまま動く**。
キーがあれば Claude API（Haiku）が業種のトーンでさらに推敲する。

---

## これは何か

求人情報（職種名・会社名・魅力ポイント・応募資格・待遇等）を渡すだけで求人票を生成し、
候補者情報（ハイライト経歴）も渡せば、その求人票を土台にしたスカウトメールも生成するデモです。
生成と同時に、年齢・性別等の禁止表現（職業安定法・男女雇用機会均等法上のリスクになり得る表現）を
検出するコンプライアンスチェックを実行します。

| 想定客 | 提供形態 |
|---|---|
| 企業の採用担当者（中小企業の人事・採用担当・スタートアップの現場マネージャー） | 求人情報を入力→求人票・スカウトメールをテキスト納品 |

`research/ai-microproducts-2026-06.md` 候補16「AI求人票・スカウトメール自動生成代行」に対応する実証デモです。
候補1〜15はいずれもBtoB/BtoC問わず「求人・採用」領域に触れる商材が無く、想定客・提供形態のいずれも
既存候補と重複しない新規カテゴリとして追加しました。

## スコープの注意（重要・法務リスク確認済み）

本デモは求人票・スカウトメールの**文章生成のみ**を対象とする。候補者の選定・推薦・面接調整等の
「あっせん」行為は一切行わない。

- **職業安定法上の位置づけ**: 職業安定法第30条の「有料職業紹介事業」（求人者・求職者の間を実際に
  あっせんし、雇用関係の成立を媒介する行為）に該当するには厚生労働大臣の許可が必要。一方、本デモの
  スコープである「求人票・スカウトメールの文章を書く（コピーライティング）」こと自体は、候補者の選定・
  推薦・マッチングを行わないため職業紹介の許可対象には該当しないと考えられる。ただし、将来的に
  「候補者を推薦する」「面接を調整する」等の機能拡張を行う場合は、都道府県労働局への確認・許可取得の
  要否を再検討する必要がある（本デモの範囲では発生しない）
- **市場での実出品確認**: 同種の「求人票専用AI・スカウト文作成」を明記したココナラ出品
  （[応募されやすくなる求人票の専用AIを作ります](https://coconala.com/services/3953433)・6,000円・2026-07-23確認）が
  現在も出品中であり、コピーライティング範囲のサービスとして市場で受容されていることの傍証となる
- **コンプライアンスチェック機能の位置づけ**: 年齢制限表現（労働施策総合推進法9条）・性別限定表現
  （男女雇用機会均等法5条）の検出はキーワードベースの簡易チェックであり、専門的な法務判断の代替には
  ならない。実案件では検出結果を「要確認ポイント」として提示し、最終判断は依頼者・必要に応じて
  社労士等の専門家に委ねる設計が前提

## アーキテクチャ: 求人情報→求人票生成＋コンプライアンスチェック→（任意）スカウトメール生成→（任意）Claude Haikuで推敲

```
求人情報（JSON: 職種名・会社名・魅力ポイント・応募資格・待遇等）
    ↓ [コンプライアンスチェック] 職種名・魅力ポイント・応募資格から年齢/性別/身体的条件の禁止表現を検出
    ↓ [求人票組み立て] 見出し＋魅力ポイント＋応募資格＋待遇をテンプレートで生成
  求人票（ルールベース・APIキー不要）
    ↓ [任意] 候補者情報（ハイライト経歴）が渡された場合のみ
    ↓ [スカウトメール組み立て] 候補者の経歴に触れた冒頭文＋求人アピール＋カジュアル面談CTA
  スカウトメール（ルールベース・APIキー不要）
    ↓ [任意] ANTHROPIC_API_KEY設定時のみ、それぞれ個別に
  テンプレート文章をプロンプトに含めてClaude Haikuへ
    ↓
  業種トーンで推敲された文章（給与・雇用形態・応募資格・経歴への言及等の事実は変えず文章のみ自然化）
```

### 2つのモード

| モード | 動作条件 | 実装 |
|---|---|---|
| **ルールベース** | APIキーなし（デフォルト） | 求人情報のフィールドを組み合わせたテンプレートで生成（純Python・ゼロ依存） |
| **ルールベース＋Claude API** | `ANTHROPIC_API_KEY` 設定時 | テンプレートを土台に claude-haiku-4-5 が業種トーンで推敲 |

どちらも同じCLIで動く。APIキーなしでもデモとして完全に機能する（推敲失敗時もテンプレート文章にフォールバック）。

## 動かし方

### 前提
- Python 3.9 以上（標準ライブラリのみ。`pip install` 不要）
- Claude API を使う場合のみ `pip install anthropic`

### 基本実行（ルールベースのみ）

```bash
# ITエンジニア求人＋候補者スカウト（求人票・スカウトメール両方を出力）
python3 job_posting_writer.py sample/job_01_it_engineer_scout.json

# 営業職求人（候補者情報なし・求人票のみ・禁止表現を検出するサンプル）
python3 job_posting_writer.py sample/job_02_sales_with_flagged_expression.json
```

### Claude APIを使う場合（業種トーンで推敲した文章も生成）

```bash
export ANTHROPIC_API_KEY="sk-ant-xxxx"
python3 job_posting_writer.py sample/job_01_it_engineer_scout.json
```

### 自分の求人情報を渡す

入力JSONは `job`（必須）と `candidate`（任意・スカウトメールを生成する場合のみ）の2キー構成。

`job`の必須フィールドは `job_title`（職種名）・`company_name`（会社名）・`appeal_points`（魅力ポイントのリスト・1件以上）。
`employment_type`（`正社員`/`契約社員`/`パート・アルバイト`/`業務委託`・省略時は`正社員`）・
`industry`（`it`/`medical`/`sales`/`general`・省略時は`general`）・`salary_range`・`work_location`・`requirements`は任意。

`candidate`の必須フィールドは `candidate_highlight`（候補者の経歴ハイライト）。`candidate_name`は任意。

```json
{
  "job": {
    "job_title": "職種名",
    "company_name": "会社名",
    "appeal_points": ["魅力ポイント1", "魅力ポイント2"],
    "industry": "it",
    "employment_type": "正社員",
    "salary_range": "年収帯",
    "work_location": "勤務地",
    "requirements": ["応募資格1"]
  },
  "candidate": {
    "candidate_name": "候補者名（任意・スカウトメール生成時のみ）",
    "candidate_highlight": "候補者の経歴ハイライト（スカウトメール生成時は必須）"
  }
}
```

```bash
python3 job_posting_writer.py /path/to/your_job.json
```

## Web版（ローカル・依存ライブラリなし）

CLIだと非エンジニアのクライアント（人事担当者・採用代行事業者）には見せられないため、ブラウザで
求人情報を入力→求人票・スカウトメールを生成できる最小Webサーバーを同梱している
（`job_posting_writer.py` の求人票組み立て・コンプライアンスチェック・スカウトメール生成ロジック
`generate_job_posting`/`generate_scout_message` をそのまま再利用、新規pip依存なし）。
本デモの差別化要素であるコンプライアンスチェック（禁止表現検出）の結果は、Web版でも常に明示的に表示する。

```bash
cd job-posting-writer
python3 server.py
# または任意のポートを指定
python3 server.py --port 8771
```

起動後、ブラウザで `http://localhost:8771` を開くと入力フォーム（職種名・会社名・魅力ポイント・
応募資格・待遇等、任意で候補者の経歴ハイライト）が表示される。「求人票を生成する」を押すと、
求人票（ルールベース）とコンプライアンスチェック結果（✅検出なし／⚠検出あり＋該当箇所）が即座に表示され、
候補者の経歴ハイライトを入力した場合はスカウトメールもあわせて生成される。`Ctrl+C` で停止。

API経由で直接叩く場合（動作確認・自動テスト向け）:

```bash
curl -X POST http://localhost:8771/generate \
  -H "Content-Type: application/json" \
  -d '{
    "job": {
      "job_title": "バックエンドエンジニア",
      "company_name": "株式会社サンプルテック",
      "appeal_points": ["フルリモート勤務・フレックスタイム制で裁量をもって働ける"]
    }
  }'
```

`ANTHROPIC_API_KEY` 未設定でもCLI同様ルールベーステンプレートのみで動作する（推敲文は生成されない）。

## 技術的補足

**コンプライアンスチェックを求人票生成と分離している理由**

`detect_prohibited_expressions`（キーワード検出）と `build_job_posting_text`（テンプレート生成）を
独立した関数に分けることで、チェック対象の禁止表現辞書だけを拡張（例: 差別的な国籍・障害関連の表現追加）
したい実案件のカスタマイズに対応しやすい設計にしている。求人票・スカウトメールの両方が同じ
`check_job_compliance` を通るため、チェック漏れが起きにくい。

**求人票とスカウトメールで同じ求人情報を再利用する設計**

`job` dict を一度 `validate_job` で正規化すれば、`build_job_posting_text`（求人票）と
`build_scout_message_text`（スカウトメール、`candidate` と組み合わせ）の両方に渡せる。
同じ魅力ポイント・待遇情報が求人票とスカウトメールで矛盾しないことを構造的に保証する。

**Claude Haiku推敲の位置づけ**

ルールベーステンプレートは「給与・雇用形態・応募資格・候補者の経歴への言及」という事実関係を保証する。
`ANTHROPIC_API_KEY` 設定時は、そのテンプレートを土台に文章の自然さだけをClaude Haikuに改善してもらう
設計にすることで、事実の正確性（テンプレート側）と文章の魅力（LLM側）の役割分担を明確にしている
（`ec-description-writer`/`review-reply-writer`/`essay-feedback`と同じ設計思想）。

**未検証事項**

- 実際のIndeed・Wantedly・エン転職等の求人媒体への投稿、候補者への実際のスカウトメール送信は行っていない（テキスト生成デモに留まる）
- コンプライアンスチェックはキーワード一致による簡易検出であり、専門的な法務判断の代替にはならない。検出できる禁止表現も年齢・性別・身体的条件の3カテゴリに限定されており、国籍・障害等の他の差別的表現カテゴリは未対応
- `research/ai-microproducts-2026-06.md` 候補16の価格検証で確認した実出品は2件（求人票・スカウト文作成AI＝6,000円／スカウトメール添削・代行＝5,000円+2,000円）に留まり、単一ソース同等の限られたサンプルのため相場としての一般化はできない

## このデモが示せること

- コンプライアンスチェック（年齢・性別・身体的条件の禁止表現検出）を求人票生成プロセスに組み込むことで、
  既存市場の類似サービス（求人票専用GPT構築）にない「法務リスクの事前検知」という差別化要素を実証している
- 求人票とスカウトメールが同じ `job` 情報を共有する設計により、両方の文書間で内容の矛盾が起きない構造
- APIキー依存ゼロの最小構成（顧客へのデモが即できる）
- LLM切り替えを環境変数で抽象化した設計（他デモ＝ec-description-writer/review-reply-writer/essay-feedbackと共通のパターン、本番拡張への接続性）

実際の受注案件では、コンプライアンスチェック辞書の拡張（国籍・障害等）・複数職種の一括処理（CSV入力）・
Indeed/Wantedly等の求人媒体別の文体調整（`ec-description-writer`の媒体別テンプレートと同型の拡張）に
応じてカスタマイズします。
